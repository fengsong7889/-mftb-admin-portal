## 0. 已确认的业务口径（决策基线，勿改）

- **档案归属唯一**：每份耗材档案只属于一个「所属品牌」（閃蜂 / mFood，取自 `sys_company_brand`）+ 一个「购买公司」（`sys_purchase_company` 字典）；同款耗材由不同品牌/公司购买须**分别建档，禁止共用**。
- **库存隔离维度**：归属固定在档案上，库存最小单元仍是「耗材档案 + 仓库」，`biz_eam_consumable_stock` 唯一键保持 `(item_id, location_id)` 不变。
- **计价**：移动加权平均；每次入库更新均价，领用出库时冻结当次成本；不用先进先出批次。
- **消耗确认时点**：发放出库即确认消耗，不新增“员工登记实际使用”。
- **出库成本**：严禁用档案参考单价 `ref_price` 代替实际入库成本。
- **统计目标**：分别核算 公司采购金额 / 剩余库存金额 / 部门消耗金额 / 员工消耗金额（数量 + 实际成本两个口径）。

### 1.2 阶段 B：成本记账引擎 + 领用改“待发放/已发放”

- **移动加权平均入库**：`EamConsumableStockMapper.inbound(...)` 重写为 `INSERT ... ON DUPLICATE KEY UPDATE`，按 `avg_cost = (total_cost+amount)/(qty+入库qty)` 原子更新，并写入归属快照 + `updated_by`。服务层 `inbound()` 强制要求实际入库单价、校验档案归属，`amount = qty × 单价`。
- **领用状态机改造**（`EamConsumableClaimServiceImpl`）：
  - `submit()`：改为**仅占用库存 + 状态 pending（待发放）**，不再自动出库；预校验「启用 + 归属已设置 + 整单同品牌同公司 + 按耗材 itemId 合并单次限领量」；明细快照 `company_brand/purchase_company_id/returned_qty`。
  - `issue()`：接受 `pending`（新）或 `approved`（历史）→ `deductOnIssue`（扣 qty+locked 并写回基于 `FOR UPDATE` 快照算出的 `newTotalCost`，清仓置 0 防尾差）→ 按当次 `avg_cost` 结转 `claim_item.actual_unit_cost/amount`、写 `out_claim` 流水（负金额）、汇总回写 `claim.cost_amount`。
  - `approve()`/`cancel()`：保留兼容历史单。
- **流水归属与成本**：`biz_eam_consumable_txn` 新增 `amount/company_brand/purchase_company_id/department_id/department/applicant_id/applicant_emp_id/applicant_name/biz_date/idempotency_key`（唯一键幂等）；出库/入库 `writeTxn` 均写归属与成本。
- **库存/流水审计口径**：库存列表 `updatedBy/updatedAt` 改取真实库存行（不再取档案）；`StockVO` 增 `avgCost/totalCost/companyBrand/purchaseCompanyName`；`TxnVO` 增 `amount/department/applicantName/...`。
- **前端**：
  - `Claim/constants.ts`：pending 文案「待審批」→「待發放」。
  - `ClaimForm.tsx`：**修正领用人契约**（下拉 value 用 `sys_user` 主键 id、默认按工号匹配当前人，避免原 `Number(工号)`=NaN/类型不符）；提示改「提交后待仓管发放」。
  - `ClaimList.tsx`：新增「待發放」Tab + 行内「發放」操作（`issueConsumableClaim`）。
  - `ClaimDetail.tsx`：pending 操作改「拒絕 / 確認發放」；明细列展示成本单价(`actualUnitCost`)/成本金额(`amount`)；合计优先用 `claim.costAmount`。
  - `StockList.tsx`：新增「加權均價 / 庫存成本」列。
  - `StockTxnList.tsx`：新增「成本金額 / 領用人 / 部門」列。
