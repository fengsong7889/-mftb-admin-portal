# 投流广告配置前端优化方案

## 范围与业务边界
- 本次执行第一阶段，只改算法库投流新增、编辑、详情及相关前端测试。
- 已确认目标：同订单同标签商家与用户各加 1；兴趣匹配优先；本期外卖到家。
- 标签回写、APP 推荐、曝光扣量尚未开发；界面明确区分目标口径与现存配置，不宣称已经执行。
- 不修改后端、数据库、销售定价或订单模块；不启动服务、浏览器、构建、提交或部署。
- 保持现有参数名称、默认数值、覆盖率及衰减公式；历史策略如实保留，兴趣优先评分与计数契约在后续阶段落地。

## 配置页面与组件
- 从 `src/pages/Recommend/AlgorithmAdd.tsx` 抽出 `TrafficAlgorithmConfig` 专属目录；保留父页面路由、品牌名称字段及已有保存 API。
- 页面五组：基础与可用性、兴趣匹配、展示频控、冷启动与浏览后相似推荐、高级策略。
- 五组使用白色模块卡片、28px 图标、15px 标题与延伸分隔线；高级策略默认折叠，其他组可折叠。
- 常驻配置摘要与分组导航；摘要由当前表单值派生，包含统计范围、阈值、频控及相似推荐开关；空值显示待配置。
- 高级组承载衰减、新标签加速及技术检查周期；保留全部原参数、开关条件和优先级选项。
- 将“生成式推荐”在新界面命名为“浏览后相似推荐”；说明原始订单计数与推荐有效分不同。
- 沿用现有翻译键，新业务说明暂用中文，待界面确认再统一国际化。

## 表单状态与兼容
- 在投流专属配置文件集中声明字段类型、默认值、分组映射与读写白名单；统一用于回填和提交。
- 补存已有的商家状态与一致性检查周期，保留 false、0、历史枚举和关闭功能的子参数。
- 折叠只隐藏内容、不卸载字段；关闭功能的子字段停止必填校验但保留值。
- 增加必填、数值范围、探索数量小于标签上限、冷启动至少一个维度、启用热门时至少一个指标的前端校验；不替代服务端校验。
- 首个错误自动展开所在组并滚动定位；显示错误汇总与快捷定位。
- 投流保存中显示 loading，并用同步提交锁防连点；详情模式没有保存入口。
- 投流详情加载失败时阻止保存默认值覆盖原配置，提供重试反馈；不改动其他算法的数据载入语义。

## 验证与验收
- 执行 `npm run typecheck`、`npm run lint`。
- 增加并运行投流参数读写与组件交互测试：false/0 保留、历史值回填、折叠字段不丢失、条件校验、错误展开、摘要联动、只读模式、保存防重及漏存回归。
- 使用 React 组件质量检查清单核对 Hooks、类型、安全与可维护性。
- 验收：投流配置从多算法大文件独立；所有现有字段仍可配置；摘要与输入一致；错误可定位；新增、编辑、详情保持统一结构。
- 浏览器视觉验收由用户进行，本轮不自动打开浏览器。

## 后续阶段与回滚
- 界面确认后：统一国际化、接入真实定价与下单 API、隔离演示订单、修正报价与退款口径。
