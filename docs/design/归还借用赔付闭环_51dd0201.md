# 归还管理与借用、赔付闭环

## 方案与范围
- 选择“管理员直接验收”：拥有 `asset-return:edit` 权限的资产管理员登记即确认；不限定必须为超级管理员，不开放员工直接释放资产。
- 单资产、一物一码；支持领用归还、借用归还、独立选择在用资产、他人代还。
- 正常归还立即释放；损坏/遗失自动建立待定责记录，不默认员工有责、不自动扣款。
- 补齐借用登记、列表、详情、续借及归还；补齐赔付定责、免赔、分次收款及遗失找回后的人工复核。
- 本期不建设员工归还申请、多级审批、批量跨仓交接、完整维修工单系统、财务总账或实际支付渠道。维修后的验收结果可以登记，不将 Mock 维修入口当成真实流程。

## 已核实的复用点
- `AssetReturn/index.tsx`、`ReturnList.tsx`、`ReturnForm.tsx`、`/asset-return` 路由和菜单种子已经存在，不重复创建菜单。
- `EamReturn`、`EamReturnMapper`、`biz_eam_return`、`biz_eam_claim_evidence`、`eam_return` 编号规则已经存在，采用增量扩展。
- `EamClaimServiceImpl.returnAsset()` 已实现简单领用归还，将其收敛到统一归还服务。
- 借用、独立归还、赔付当前仍由 `src/api/eam.ts` 中的 Mock 承载；部分资产操作明确返回未实现错误，不能仅替换页面而保留这些写入链路。

## 业务规则与状态

### 归还与实物处置
| 场景 | 原领用/借用 | 资产状态 | 后续处理 |
|---|---|---|---|
| 正常收回 | `returned`，回填归还 ID/日期 | `idle` | 无赔付待办 |
| 损坏收回 | `returned`，回填归还 ID/日期 | 新增 `pending_disposal` | 自动建待定责记录；检测/维修后验收恢复，或登记报废结果 |
| 遗失登记 | `returned`，明确展示“遗失结案，未收回” | 新增 `lost` | 自动建待定责记录，禁止再领用 |
| 遗失找回 | 不重新开启旧领用/借用 | 正常则 `idle`，损坏则 `pending_disposal` | 追加找回记录、时间和证据，保留原始遗失事实 |

- 归还记录状态：`completed`（正常完成）、`exception_pending`（异常处理中）、`exception_closed`（实物处置与责任处理均结束）；资产状况 `condition` 单独筛选，不再混用 `status`。
- 资产实物处置与赔付进度独立：赔完钱不能自动变闲置；维修验收完成后，即使赔付未结也可以恢复使用。
- 解除占用时显式写 SQL NULL：`current_holder_id`、`active_claim_id`、新增 `active_borrow_id`、当前 `user_name`；`hold_type` 恢复 `owned`。不依赖 `setX(null) + updateById()`。
- 保留公司品牌、资产权属、原购置及首次使用日期；不硬编码归属部门为“物资部”。正常/损坏收回选择有效存放位置，遗失时不伪造入库位置。
- 原持有人、实际归还人/报失人、代还原因、验收操作人分别记录；解除占用不抹去历史责任证据。
- 独立选资产由后端解析有效来源。存在有效领用/借用时强制关联；来源 ID 不匹配、多个有效来源、状态冲突均拒绝。确无来源的历史在用资产允许管理员显式选择“历史资产归还”，填写原使用人和原因，不按姓名猜测员工 ID。
- 所有日期由后端复核：归还日期不得早于来源开始日期或晚于业务当天；支持逾期归还。签收状态与归还状态独立，不伪造补签。

### 借用
- 新增 `EamBorrow` 实体、Mapper、DTO/VO、Service、Controller；字段包含员工 ID、姓名/部门快照、借出日期、到期日、用途、续借次数、归还 ID、审计字段。
- 借用仅允许真实闲置且未被领用/借用/异常处置占用的资产；员工从真实员工数据选择，部门使用组织树。
- 持久化状态采用 `borrowing/returned`；`overdue` 由未归还且到期日早于当天计算，列表筛选与展示口径一致。
- 续借必须晚于旧到期日且不早于当天；已归还不能续借。登记、续借、归还均留事件记录。

### 异常与赔付
- 损坏/遗失同一事务自动创建一张关联归还单的 `pending` 待定责记录；原持有人仅作参考，不自动填成责任人。
- 原因分类沿用人为、自然损耗、第三方、质量问题；责任对象支持员工、供应商/第三方、公司承担。免赔须填写原因，不强迫选择员工。
- 状态：`pending → confirmed → partially_paid → paid`；待定责可走 `waived`。金额由后端使用 `BigDecimal/DECIMAL(18,2)` 计算，沿用 MOP。
- 每次收款单独保存金额、业务日期、凭证、操作人、请求 ID；金额必须大于零且不得超过未收余额。只登记已发生的收款，不执行实际支付。
- 找回后自动要求责任复核，不改写原赔付记录、不自动退款；复核记录保留原金额和调整理由。已收超过复核金额时进入 `refund_pending`，通过独立退款登记冲减，退款不得超过应退余额。
- 检测/维修后恢复、报废结果、遗失核销、找回均通过专用处置接口登记，要求原因及相应证据；不提供任意改状态接口。资产增加当前异常归还关联，处置须校验关联，防止旧归还单改变已重新领用资产。

## 后端与 API 契约
- 新增 `EamReturnService/Impl`、`EamReturnController` 及明确 DTO/VO，扩展现有实体与 Mapper。
- `/api/eam/returns`：`GET` 分页、`POST` 登记；`GET /candidates` 分页搜索可归还资产；`GET /context` 按 `claimId/borrowId/assetId` 获取受控预填；`GET /{id}` 详情；`POST /{id}/dispose` 处置；`POST /{id}/recover` 找回；凭证受控读取。
- `/api/eam/borrows`：分页、详情、登记、`POST /{id}/renew`；归还统一调用 returns，不在前端串联资产更新和借用关单。
- `/api/eam/compensations`：分页、详情、独立登记、定责、免赔、收款、找回复核、退款登记。来自归还的记录复用自动建立的单据，不能再次创建或由前端分两次请求绑定。
- 归还请求包含来源标识、业务日期、状况、原因、实际归还人/代还原因、收回位置和凭证；编号、操作人、状态、原持有人和关联赔付 ID由服务端产生。
- 保留旧 `/api/eam/claims/return` 作为兼容适配，委托统一服务并保留返回 ID；缺省状况为正常，旧客户端仍须通过相同来源校验和归还权限。新前端全部进入登记页。
- 查询返回 `Result<PageResult<VO>>`，单据详情返回明确 VO；用 Bean Validation、枚举白名单和现有异常处理体系。补充 SpringDoc 契约注解。
- 借用/归还/赔付 API 使用独立 `src/api/eamBorrow.ts`、`eamReturn.ts`、`eamCompensation.ts`；旧 `eam.ts` 只保留必要兼容导出，移除这些流程的 Mock 写入和失败降级成功。

### 事务、并发与权限
- 统一锁顺序：资产 → 来源单 → 归还/赔付单 → 编号序列。归还记录、来源关单、资产更新、凭证、异常单、事件必须在同一事务内完成，任一失败全部回滚。
- 写接口携带幂等键并持久化请求摘要和结果；同键同内容返回原结果，同键不同内容拒绝。来源唯一约束防止不同键重复归还，收款/退款也防重复入账。
- 领用登记/签署/取消同步补齐必要占用边界：统一资产锁、待签领用预占、签署前重验、取消只释放本单占用；修正现有先改成 cancelled 再判断旧状态的释放逻辑。
- 普通资产编辑/删除不得绕过借用和异常占用保护，禁止把遗失/待处置资产手动改成闲置。
- 权限：对应菜单 `view` 查询、`edit` 办理；归还入口要求 `asset-return:edit`，定责和收退款要求 `asset-compensation:edit`，借用登记续借要求 `asset-borrow:edit`。前端隐藏按钮只是 UX，服务端独立校验。
- 沿用当前后台菜单授权的管理范围，不虚构租户字段；逐项验证来源单、资产、员工、凭证与归还单关联，未知或不匹配默认拒绝。操作人取登录上下文，禁止信任请求中的 operator。

## 数据库迁移与审计
- 新增 `backend/sql/151_eam_return_management.sql`，在 `DataInitializer` 中按独立版本幂等执行等效迁移，不重跑全部菜单种子、不删除历史记录。
- 扩展 `biz_eam_return`：可空 `claim_id`、`borrow_id`、来源类型、状况、处理状态、原持有人/资产快照、实际归还人、代还原因、是否收回、收回位置、实物处置、赔付关联和审计字段。
- 扩展 `biz_eam_claim_evidence`：`claim_id` 可空，新增 `return_id`；`storage_path` 从 VARCHAR(500) 扩为 MEDIUMTEXT，兼容现有签名。多附件以 `return_id` 关联，保留旧单凭证引用。
- 凭证本期限制 PNG/JPEG，单次最多 5 张、每张解码后不超过 512 KiB；前端压缩仅作 UX，后端验证 Base64、魔数、大小、像素上限并重新编码、计算真实摘要。不接受任意外链/SVG，不在列表携带图片内容。异常说明必填，遗失允许无实物照片。
- 新建 `biz_eam_borrow`、`biz_eam_compensation`、`biz_eam_compensation_payment`、`biz_eam_asset_event`、`biz_eam_operation_request`。事件追加记录来源、资产、前后状态、操作者、时间、请求 ID；领用归还同时写既有 `biz_eam_claim_event`。
- 设置来源互斥检查、归还单号/来源唯一约束、赔付来源唯一约束、幂等键唯一约束、金额约束、必要关联及查询索引。给资产补 `active_borrow_id` 和当前异常归还关联。
- 原有归还保留编号与业务事实，缺失状况显示“历史未记录”，不从自由文本猜测损坏/遗失，不自动补造赔付；加约束前检查重复/孤儿记录，有冲突则停止并报告，不擅自清理。
- 沿用 `eam_return` 的 `GH + YYYYMMDD + 4位`，修正业务菜单归属；新增借用 `JY`、赔付 `PF` 同类编号规则。沿用现有序列起点，不重置计数器；4位耗尽明确报错，禁止重号或静默变5位。
- 迁移只修复归还菜单缺失/删除/父级异常，复用 `asset-management → asset-flow-ops → asset-return`，保留既有 ID、授权与自定义排序。

## 前端页面与交互
- 扩展现有三个模块而非另起一套页面；业务请求、状态和类型从页面抽离到 Hooks/API，新增 schema 用于输入及响应校验。第二阶段引入 Zod 并锁定版本，安装使用 `--legacy-peer-deps`，核查许可证与依赖风险。
- 归还路由：`/asset-return`、`/asset-return/add?claimId=...`、`/asset-return/add?borrowId=...`、`/asset-return/detail?id=...`、独立处置/找回表单。旧 `?borrowId=` 自动规范化到 add；无效 ID、冲突参数显示错误，不能退化为自由登记。
- 借用采用列表、add、detail、renew 深链；赔付采用列表、detail、edit/定责、payment、review 深链。旧 `?id=`、`?returnId=&assetId=` 链接兼容并由后端查关联。
- 领用详情“归还”改为跳转登记页，取消一键正常归还；借用列表和详情统一跳转。正常/异常登记成功都展示归还详情；异常提供“立即处理/稍后处理”，稍后不会丢待办。
- ReturnList 展示归还单号、来源单、资产、原持有人、实际归还人、业务日期、状况、处理状态、赔付进度；支持关键词、来源、状态、状况、日期过滤及真实分页。
- ReturnForm 分为来源/资产、归还信息、验收状况、凭证模块。自动带出持有人和操作人，远程分页搜索资产/员工；代还才展开原因，损坏/遗失展开异常说明，不一次加载全部资产。
- ReturnDetail 展示不可变归还事实、关联单据、凭证和处理进度，底部操作记录仅最后更新人/时间；完整事件通过独立受控记录视图/API查看，不堆在详情底部。
- 新增资产状态同步到 API 类型、台账统计/筛选、详情和标签展示；所有状态集中为常量，禁止未知状态导致页面崩溃。
- 表单严格采用 `form-page-style.md`：橙色渐变头部、白色 div 模块、vertical Form、底部 `.form-footer`；只读详情隐藏提交按钮，复杂编辑/收款/定责不用 Modal。
- 列表统一搜索区、操作区、`useColumnConfig` 和分页；部门为 `TreeSelect`；先表单校验再 `custom-confirm-modal` 二次确认，错误不重复 toast，处理竞态、失败重试、空态和按钮防连点。

## 回滚与交付边界
- 只做本地实现与验证，不自动提交、推送、部署或执行生产迁移。
- 数据库采用增量扩展，保留旧字段与历史记录；提供迁移回滚步骤，已有新业务数据时禁止直接删列删表。
- 新业务启用后不能直接回退到缺少占用校验的旧写接口；先暂停相关写入口并处理新状态，再回滚到具备兼容保护的版本。配置及菜单回滚不删除业务数据。
- 交付列出变更文件、API/权限契约、验证结果、迁移注意事项和未覆盖风险；不把静态预览、Mock 演示或仅编译成功当成完整闭环验收。
