## 设计方案

采用**回收站模式**：
- 删除对话 -> 进入回收站（软删除，`deleted=1`，记录 `deleted_at`）
- 回收站中的对话**永久保留**，直到用户手动"永久删除"
- 用户可在回收站中点击"恢复"将对话还原到聊天标签栏
- 审计菜单的对话记录不受任何影响（已有独立的审计 SQL，绕过 `@TableLogic`）

## 后端改动

### 1. 数据库迁移 — `AiConversationDataInitializer.java`
- 新增版本 `ai_conversation:v4`，补列 `deleted_at DATETIME DEFAULT NULL COMMENT '删除時間戳'`

### 2. 实体 — `AiConversation.java`
- 新增字段 `private LocalDateTime deletedAt`，标注 `@TableField(fill = FieldFill.UPDATE)` 和 `@TableLogic` 无关，仅做记录用

### 3. Mapper — `AiConversationMapper.java`
新增 3 个自定义方法（绕过 `@TableLogic`）：
```java
// 查询当前用户已删除的对话（按删除时间倒序）
@Select("SELECT * FROM ai_conversation WHERE username = #{username} AND deleted = 1 ORDER BY deleted_at DESC")
List<AiConversation> selectDeletedByUsername(...)

// 恢复对话：deleted=0, deleted_at=NULL
@Update("UPDATE ai_conversation SET deleted = 0, deleted_at = NULL, updated_at = NOW() WHERE id = #{id} AND username = #{username} AND deleted = 1")
int restoreById(...)

// 永久删除（硬删除）
@Delete("DELETE FROM ai_conversation WHERE id = #{id} AND username = #{username} AND deleted = 1")
int permanentDeleteById(...)
```

### 4. Service — `AiConversationService.java` + `AiConversationServiceImpl.java`
- 新增 `listDeletedConversations()` — 返回当前用户已删除的对话列表
- 新增 `restoreConversation(Long id)` — 恢复对话（若活跃会话已达上限，自动归档最旧的活跃会话）
- 新增 `permanentDeleteConversation(Long id)` — 永久删除
- 修改 `deleteConversation(Long id)` — 在软删除时同时设置 `deleted_at = NOW()`（通过自定义 SQL 替代 `deleteById`）

### 5. Controller — `AiConversationController.java`
新增 3 个端点：
```
GET    /api/ai/conversations/deleted       — 列出我已删除的对话
POST   /api/ai/conversations/{id}/restore   — 恢复对话
DELETE /api/ai/conversations/{id}/permanent  — 永久删除
```
