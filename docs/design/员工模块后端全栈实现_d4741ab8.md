### 2.6 在职状态派生逻辑

在 `EmployeeServiceImpl.list()` 和 `EmployeeVO.from()` 中：
1. 查询该员工最新职务记录（`effective_seq` 最大的记录）
2. 若最新记录的 `operation = '离职'` → `employmentStatus = "resigned"`
3. 否则 → `employmentStatus = "active"`
4. 列表查询时，使用子查询或 JOIN 批量派生，避免 N+1 问题

**SQL 思路（列表查询优化）：**
```sql
SELECT u.*, 
  (SELECT pr.operation FROM emp_position_record pr 
   WHERE pr.user_id = u.id AND pr.deleted = 0 
   ORDER BY pr.effective_seq DESC LIMIT 1) AS latest_operation
FROM sys_user u
WHERE u.deleted = 0
-- 然后 Java 层根据 latest_operation 派生 employmentStatus
```

## 四、关键约束

- `sys_user.status` 字段保留（1=启用/0=停用），用于账号级别的启用/停用控制
- `employmentStatus` 是派生字段，不落库，由职务记录实时计算
- 职务记录的 `effective_seq` 新增时取当前最大值+1，编辑时+1
- 职务记录中「重新入职」选项仅当最新记录操作为「离职」时可选（前端已实现 disabled 逻辑）
- 所有新表遵循项目现有规范：逻辑删除、createdAt/updatedAt 自动填充、operatorResolver 记录操作人
