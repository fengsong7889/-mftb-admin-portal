# R-24: 安全测试体系实施计划

## 前置依赖

pom.xml 已有 `spring-boot-starter-test` 和 `spring-security-test`，仅需新增 H2 内存数据库依赖用于集成测试。

---

## Phase 1: 测试基础设施（3 个文件）

### 1.1 添加 H2 测试依赖

**文件**: `backend/pom.xml`

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>test</scope>
</dependency>
```

### 1.2 创建测试专用配置

**文件**: `backend/src/test/resources/application-test.yml`

- H2 MySQL 兼容模式数据源（`MODE=MySQL`）
- 禁用 DataInitializer（`init.enabled=false`）避免启动时执行生产迁移脚本
- 禁用定时任务（避免 SchemaVersionTracker 等干扰）
- JWT 测试密钥（固定值，仅测试用）
- 日志级别 `WARN`（减少测试输出噪音）

### 1.3 创建测试基类

**文件**: `backend/src/test/java/com/mftb/admin/security/SecurityTestBase.java`

核心能力：
- `@SpringBootTest` + `@AutoConfigureMockMvc` + `@ActiveProfiles("test")`
- `@Transactional` 每个测试自动回滚
- 辅助方法：`loginAs(username)` → 调用 JwtUtil 生成 token → 返回 `Authorization` header 值
- 辅助方法：`request()` → 返回预配置 MockMvc RequestBuilder（带 token）
- 预置测试用户：通过 `@Sql` 或 `@BeforeEach` 插入 admin / guest / normal 三种角色用户
- 预置测试菜单和权限数据：`sys_menu` + `sys_role` + `sys_role_menu` + `sys_user_role`

### 1.4 创建测试 Schema 初始化

**文件**: `backend/src/test/resources/schema-test.sql`

精简版建表脚本，仅包含安全测试所需的核心表：`sys_user`、`sys_role`、`sys_user_role`、`sys_menu`、`sys_role_menu`、`sys_department`，以及被测试的业务表（如 `biz_employee`）。使用 H2 兼容语法。

## Phase 2: 权限矩阵测试（~8 个测试类）

**目标**: 验证每个 API 端点是否正确拒绝了无权限用户的请求。

### 2.1 认证层测试

**文件**: `backend/src/test/java/com/mftb/admin/security/AuthenticationTest.java`

| 测试用例 | 预期 |
|---------|------|
| 无 Token 访问 `/api/employees` | 401 |
| 过期 Token 访问任意 API | 401 |
| 篡改 Token 访问任意 API | 401 |
| 白名单路径 (`/api/auth/login`) 无需 Token | 200 |
| 已停用账号 Token 访问 API | 1002 (ACCOUNT_DISABLED) |

### 2.2 敏感管理接口权限矩阵

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/EmployeePermissionTest.java`

针对 `EmployeeController`（18 个 `@RequirePermission`）：
- admin 用户 → 所有操作 200
- guest 用户 → 所有操作 403
- 仅有 view 权限的用户 → GET 200, POST/PUT/DELETE 403

### 2.3 角色与权限管理接口

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/RolePermissionTest.java`

针对 `RoleController`（8 个 `@RequirePermission`）：
- 非 admin 用户创建角色 → 403
- 非 admin 用户修改权限配置 → 403
- 删除角色 → 仅 role-management:delete 权限用户可操作

### 2.4 菜单管理接口

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/MenuPermissionTest.java`

针对 `MenuController`：
- 菜单树查询 (`/tree`) → 所有登录用户可访问（无 `@RequirePermission`）
- 菜单 CRUD → 仅 menu-config 权限用户

### 2.5 无权限注解接口审计

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/UnprotectedApiAuditTest.java`

**这是最关键的安全测试** — 审计所有无 `@RequirePermission` 的 Controller，验证是否合理：

| Controller | 是否需要补权限 | 分析 |
|-----------|---------------|------|
| `AuthController` | 否（登录/登出/会话检查本身无需权限） | 但 `/api/auth/info`、`/avatar` 等需确认仅需认证 |
| `McpExecController` | 需评估（登录即可执行外部工具） | 高风险，需确认是否应加权限注解 |
| `LlmUsageController` | 部分（上报仅需认证，但 summary/records 可能需要限制） | 需确认 |
| `BizSeqRuleController` | 是（编号规则管理属于系统配置） | 应加权限注解 |
| `CardOrderController` | 需评估 | 需确认 |
| `IconfontController` | 需评估 | 需确认 |
| `NotificationController` | 需评估 | 需确认 |

测试方式：用 guest 用户调用这些接口，记录哪些返回 200（仅认证无授权），生成审计报告。

### 2.6 财务模块权限

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/FinancePermissionTest.java`

针对 `FinApprovalController`（10 个）、`FinRiskController`（5 个）等财务接口：
- 财务审批操作需要对应权限
- 风险操作（核销、冲销）需要高级权限

### 2.7 AI 模块权限

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/AiPermissionTest.java`

针对 `AiEmpAuthController`（12 个）、`AiEmpQuotaPolicyController`（10 个）等：
- 员工 AI 授权管理需要 admin 权限
- 额度策略配置需要高级权限
- 普通员工仅能查看自己的 AI 授权（`AiMyAuthController`）

### 2.8 OA 审批权限

**文件**: `backend/src/test/java/com/mftb/admin/security/permission/OaPermissionTest.java`

针对 `OaRequestController`（8 个）、`OaProcessController`（2 个）：
- 提交申请 → 所有登录用户
- 审批操作 → 仅审批人
- 流程管理 → 仅管理员

## Phase 3: IDOR 测试（~3 个测试类）

**目标**: 验证用户 A 无法通过篡改 ID 操作用户 B 的数据。

### 3.1 员工数据 IDOR

**文件**: `backend/src/test/java/com/mftb/admin/security/idor/EmployeeIdorTest.java`

| 测试用例 | 预期 |
|---------|------|
| 普通员工 GET `/api/employees/{otherId}` | 403（无 employee-management 权限）或数据过滤 |
| 普通员工 PUT `/api/employees/{otherId}/status` | 403 |
| 有 view 权限的员工查看非本部门员工 | 取决于数据权限实现 |

### 3.2 OA 审批 IDOR

**文件**: `backend/src/test/java/com/mftb/admin/security/idor/OaRequestIdorTest.java`

| 测试用例 | 预期 |
|---------|------|
| 用户 A 审批用户 B 的待审批任务 | 403 或业务拒绝 |
| 用户 A 撤销用户 B 的申请 | 403 或业务拒绝 |
| 用户 A 查看用户 B 的申请详情 | 取决于实现 |

### 3.3 财务数据 IDOR

**文件**: `backend/src/test/java/com/mftb/admin/security/idor/FinanceIdorTest.java`

| 测试用例 | 预期 |
|---------|------|
| 用户 A 操作非自己负责的财务批次 | 403 或业务拒绝 |
| 用户 A 审批非自己节点的财务审批 | 403 或业务拒绝 |

## Phase 4: 并发安全测试（~2 个测试类）

**目标**: 验证高并发场景下的数据一致性和竞态条件防护。

### 4.1 财务审批并发

**文件**: `backend/src/test/java/com/mftb/admin/security/concurrent/FinApprovalConcurrentTest.java`

| 测试用例 | 预期 |
|---------|------|
| 两个审批人同时审批同一笔财务 | 仅一人成功，另一人得到冲突提示 |
| 同一审批人快速重复提交同一审批 | 幂等处理或第二次被拒 |

### 4.2 AI 额度并发

**文件**: `backend/src/test/java/com/mftb/admin/security/concurrent/AiQuotaConcurrentTest.java`

| 测试用例 | 预期 |
|---------|------|
| 同时为同一员工修改额度策略 | 仅一人成功（唯一键约束或乐观锁） |
| 高并发上报 LLM 用量 | 额度不超发 |

实现方式：使用 Java `ExecutorService` + `CountDownLatch` 模拟并发请求。

## Phase 5: 边界值测试（~2 个测试类）

**目标**: 验证参数校验、分页边界、字段长度等输入安全。

### 5.1 分页与查询边界

**文件**: `backend/src/test/java/com/mftb/admin/security/boundary/PaginationBoundaryTest.java`

| 测试用例 | 预期 |
|---------|------|
| `page=0` 或 `page=-1` | 400 或自动修正为 1 |
| `size=0` 或 `size=99999` | 400 或限制到最大值 |
| `keyword` 超长字符串（10000 字符） | 截断或 400 |
| SQL 注入尝试（`keyword=' OR 1=1 --`） | 正常返回空结果（MyBatis 参数化） |

### 5.2 请求体边界

**文件**: `backend/src/test/java/com/mftb/admin/security/boundary/InputValidationTest.java`

| 测试用例 | 预期 |
|---------|------|
| 登录：空用户名/密码 | 400 |
| 登录：超长用户名（1000 字符） | 400 |
| 创建员工：缺失必填字段 | 400 |
| 创建角色：重复 code | 400（唯一键冲突友好提示） |
| 头像上传：非图片文件（伪造 Content-Type） | 400（Magic bytes 校验） |
| JSON 格式错误 | 400 |
| 负数金额字段 | 400 或业务拒绝 |

## 执行顺序与验证

1. **Phase 1** → 运行 `cd backend && mvn test -B` 确认基础设施可用
2. **Phase 2** → 运行测试，**预期会发现无权限注解的 API 安全问题**，记录发现
3. **Phase 3** → 运行测试，记录 IDOR 漏洞（如有）
4. **Phase 4** → 运行测试，验证并发安全
5. **Phase 5** → 运行测试，验证输入校验

最终验证：
```bash
cd backend && mvn test -B          # 所有测试通过
cd backend && mvn verify -B        # 含 Jacoco 覆盖率报告
```

## 预期发现的安全问题

测试过程中**很可能发现**以下问题（仅记录，不在本次任务中修复）：

1. 9 个 Controller 缺少 `@RequirePermission` 注解（McpExecController 风险最高）
2. 部分业务接口可能存在 IDOR（取决于 Service 层是否校验资源归属）
3. 分页参数可能缺少上限校验（`size` 无最大值限制）

这些问题将作为测试产出记录在测试注释和 `@DisplayName` 中，供后续安全加固任务处理。
