# 盘活复苏全链路实现（参照无敌星星）

## 一、数据库设计（追加至 `backend/sql/09_ad_promotion.sql` 与 `backend/src/main/resources/09_ad_promotion.sql`，幂等）

**盘活复苏差异层（新建 4 张表）：**
- `biz_ad_pricing_revive`：计价主表。字段对齐星星，去掉时段类字段：`algo_id/algo_name/brand/channel/presale_days(默认180)/refund_enabled/discount_tiers(JSON,多天梯度 [{"minDays":3,"discount":95}])/cancel_fee_tiers/block_merchant/block_list/status/remark/updated_by`
- `biz_ad_pricing_revive_region`：商圈计价明细。`pricing_id/region/daily_price/daily_sales_limit`（每天销售个数=库存）
- `biz_ad_order_item_revive`：订单明细，一行 =「商圈×日期」（无餐段）。`order_id/order_no/biz_date/region/original_price/sale_price/refund_price/delivery_status`
- `biz_ad_day_lock_revive`：加购锁 60 秒。`algo_id/biz_date/region/group_code/store_code/expire_at`，唯一键 `(algo_id,biz_date,region,group_code)`（库存>1 时多商家可分别锁同一格子）

**存量表调整：**
- `biz_ad_pricing_star_region` 增加 `daily_sales_limit INT DEFAULT 1`（默认1保持现有独家占行为兼容）
- `biz_ad_cell_lock` 唯一键改为 `(algo_id,biz_date,region,meal_slot,group_code)`（先删旧 uk 再建新 uk）
- `biz_ad_order` 增加 `gift_days INT / gift_amount DECIMAL(12,2)` 快照列
- 种子数据：预置算法 `ALG_REVIVE_001 盤活復蘇-團購版`（algo_type=3）

**`AdPromotionDataInitializer`** 增加幂等补列/改键逻辑（复用 `addColumnIfAbsent` 模式），保证存量 SQLPUB 测试库启动即升级。

## 三、后端：盘活复苏接口（完全对照星星分层）

**Entity/Mapper**：`AdPricingRevive`、`AdPricingReviveRegion`、`AdOrderItemRevive`、`AdDayLockRevive` + 4 个 Mapper（BaseMapper 风格，同 `AdPricingStarMapper`）

**DTO**：`AdPricingReviveRequest/VO`（regionPrices 含 dailySalesLimit，discountTiers 为 minDays/discount）、`AdReviveOrderRequest`（cells: bizDate+region，新增 `giftDays`）、`AdReviveInventoryVO`（cells: bizDate/region/dailyPrice/salesLimit/remaining/status）

**Controller/Service：**
- `AdPricingReviveController` `/api/ad/pricing/revive`：page/detail/active/create/update/status/delete（逻辑照抄 [AdPricingStarServiceImpl](file:///Users/yangjingjing/Desktop/SARY/backend/src/main/java/com/mftb/admin/service/impl/AdPricingStarServiceImpl.java)）
- `AdSalesReviveController` `/api/ad/sales/revive`：`/inventory`、`/lock`、`/unlock`、`/order`
- `AdSalesReviveServiceImpl`（参照 [AdSalesStarServiceImpl](file:///Users/yangjingjing/Desktop/SARY/backend/src/main/java/com/mftb/admin/service/impl/AdSalesStarServiceImpl.java)）：
  - 库存：预售窗口 = pricing.presaleDays（默认180）；格子=商圈×日期；状态=占用数+他人锁数 vs daily_sales_limit；屏蔽商家拦截
  - 下单：去重/窗口/定价校验 → 库存校验 → 多天梯度折扣（按 minDays 降序匹配）→ 赠送天数抵扣 → 余额校验（仅扣实付）→ 写订单+明细 → `FinWriteChainService.writeAdConsume`（变动类别=盤活復蘇，已存在于 AdAlgoTypeNames）→ 释放本商家锁
  - 赠送抵扣规则：抵扣金额 = round2(折后总额 ÷ 总天数 × giftDays)，封顶折后总额；`gift_days/gift_amount` 写入订单快照；明细 sale_price 按抵扣后实付等比分摊（保证退款只退推广金部分，赠送天数不返还）

**赠送模块对接（`GiftService` 新增方法 + `GiftController` 新接口）：**
- `GET /api/gifts/available-days?storeId=&adType=&brand=`：可用赠送天数合计（status=1、remaining>0、未过期）
- `deductForOrder(storeId, adType, brand, days, orderNo, algorithmId/Name)`：按过期时间 FIFO 扣减 `biz_gift_record` 并写 `biz_gift_consume`（tradeType=ad_purchase，带 orderNo/algorithmId），复用现有表结构

## 假设与说明

- 赠送天数抵扣只抵扣推广金实付；退款时不返还赠送天数（按明细 sale_price 梯度扣费退款）
- 盘活复苏无餐段维度，售卖单位 = 商圈×日期；加购锁同样 60 秒
- 星星默认 `daily_sales_limit=1`，存量数据行为不变；新定价可配置库存数
- 财务写入链、订单号生成、下单人快照等共享逻辑完全复用现有工具类
