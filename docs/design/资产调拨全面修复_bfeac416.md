# 资产调拨管理全面修复

## 业务决定与范围
- 采用「领用资产可直接调拨；借用资产必须先归还再重新借用」。借用绑定借用人、到期日及逾期责任，不通过调拨静默转移这些义务。
- 调拨仍为有权限经办人的直接登记：校验 → 二次确认 → 保存并立即生效，状态 `done`；本次不新增申请草稿、审批或预约执行阶段。
- 接收人承接领用责任，原领用人及签名保持历史真实性；建立关联承接领用记录并要求接收人补签，不复制原签名、不伪造归还。
- 影响范围以调拨模块为主，关联领用、归还、权限和资产写入路径仅做保证调拨一致性所必需的修改。既有借用调拨历史保留，只读兼容，不猜测重建责任链。

## 已确认的问题
- 搜索区已有全局 Grid，但 Input/日期控件写死宽度，导致截图中的控件长短不齐；部门选项来自硬编码数组。
- 待调拨页只有三个筛选，后端缺少持有方式查询；返回路径固定为资产台账，Tab 未持久化。
- 调拨仅修改台账，原领用／借用单仍可归还该资产；旧调拨撤销可覆盖后续归属，并且撤销没有锁资产。
- 工号查询失败会回退姓名，可能选错员工；重复提交可产生同人同部门的无效调拨。
- 仅有调拨权限的角色被资产台账、组织、分类和品牌管理接口权限阻断；详情加载失败会持续转圈。

## 列表、筛选与字段
主要修改 `src/pages/AssetManagement/AssetTransferList/` 和对应查询 API。
- 两个 Tab 使用 `.search-section` 四列 Grid、`gap: 16px 12px`；移除固定控件宽度，全部占满单元格；查询／重置复用全局 32px、13px、6px 按钮规则。
- 调拨记录保留现有十项条件，增加「资产品牌」；原部门和调入部门均改为后端组织树 `TreeSelect`。
- 待调拨页按顺序提供：资产编号 Input、资产名称 Input、资产分类 TreeSelect、资产品牌 Select、使用人 Input、所在部门 TreeSelect、持有方式 Select。
- 分类使用完整层级和稳定 ID；选中父分类查询整个子树。部门树同样支持子树，禁止硬编码或只构建两级树。历史名称型记录仅按可唯一对应的部门名称兼容，重名不得猜测。
- 后端补齐分类、品牌和持有方式的实际 SQL 筛选；查询、重置及修改分页大小回到第一页，处理请求乱序，失败时不把旧结果显示为新查询结果。
- 待调拨列表保留在用资产及持有方式筛选：借用行禁用调拨并提示先归还；来源不完整的历史资产也禁用并说明需核对领用关系。
- 两张表使用 `useColumnConfig`，新增品牌列默认可见且保留用户旧列配置；待调拨页统一为「资产品牌」「领用日期」。领用日期取当前有效领用记录日期；借用行不把借用日期冒充领用日期，显示 `—`。
- `brand/brandId` 表示资产品牌，不使用 `companyBrand` 公司品牌。记录页、详情页、表单保持一致命名及枚举映射；未知值明确显示未知，不默认当作已完成或自有领用。
- 当前导出按钮未绑定任何行为：移除无效入口及无用途勾选，导出作为后续建议，不保留可点击却无响应的功能。

## 品牌及接口契约
主要修改 `src/api/asset.ts`、调拨 Query/DTO/VO/Entity/Mapper/Service 及迁移初始化器。
- 品牌选项复用现有 EAM 品牌表及基础数据服务，与 `fetchBrandList` 保持同源；不引入静态品牌列表或 Mock 降级。
- 调拨记录新增 `brandId`、`brand` 快照，新记录以登记时资产值保存；按品牌 ID 筛选。
- 旧记录能够唯一关联现存资产时补录品牌并标识为「按现有台账补录」；无法确认的保留空值，不宣称还原了历史品牌。
- 补齐 `createdBy/updatedBy` 返回字段；将登记 API 返回类型由 `void` 修正为实际调拨 ID。
- 请求、筛选和响应均使用明确类型；状态、持有方式、长度限制用常量统一，繁中／英文文案同步更新。

## 独立表单与来源返回
主要修改 `AssetTransfer/index.tsx`、`TransferDetail.tsx`、`AssetDetail/index.tsx` 及入口路由。
- 表单结构：`.content-area` → 白色圆角头部、橙色动画顶条和返回按钮 → `Form layout="vertical"` 包裹的白色 div 模块卡片 → `.form-footer` 取消／保存；常规字段三列 Grid。
- 模块分为资产及当前持有人、接收人及调入部门、日期／原因／备注；图标色块、标题和底部按钮严格按项目规则，不覆盖全局页脚尺寸。
- 接收人通过员工选择器绑定唯一 ID，姓名／工号只读联动；部门使用启用组织树。显示真实资产状态和不可调拨原因。
- 保存前先校验，再使用 `custom-confirm-modal` 展示调出／调入人、部门、日期和原因，明确「立即生效、接收人需补签」；提交期间禁止重复操作，失败保留输入。
- 使用编码后的站内 `from` URL 保存来源；列表 Tab、筛选和分页写入 URL。返回／取消恢复原菜单、原 Tab 与查询，不依赖单纯 `navigate(-1)`。
- `from` 校验站内已注册页面，拒绝外链及自身循环；共享资产详情无来源时回资产台账，调拨页／调拨详情无来源时回调拨管理。
- 保存成功回到来源列表并刷新；来源是详情时返回该详情刷新。调拨记录的资产链接进入资产详情并携带来源，不再先跳台账搜索。
- 缺失／非法 ID、404、403 和网络失败分别显示错误／无权限及重试／返回入口，不无限加载。详情只读，不在头部放保存或撤销按钮；撤销入口放记录列表。

## 责任承接、校验与安全撤销
- 登记只接受在用、非借用、持有人与有效领用一致的资产；没有有效来源、存在未结借用或待处置归还时明确拒绝。
- 原领用新增 `transferred` 状态；保留员工、日期、内容摘要、签名和凭证。新承接领用关联调拨单与原领用，状态 `claimed`、签署状态 `proxy_pending`，`activeClaimId` 指向新记录。领用详情区分「调拨承接」与普通领用。
- 同步领用列表、个人领用、统计、签署及两处归还入口：接收人看到有效承接记录；原单不可再归还／取消；补签仅允许对应接收人并校验当前有效关系，不修改原签名。调拨生成的承接记录不能从普通领用取消入口绕过撤销规则。
- 员工以 ID／工号唯一匹配，显式工号失败不得回退姓名；提交信息冲突、员工删除／禁用、部门无效及同人同部门无变化均拒绝。
- 日期严格为有效日历日期，不晚于今日、不早于当前有效领用或最新调拨日期；查询日期非法或开始晚于结束返回校验提示。原因必填并 trim，上限 500；备注上限 512；撤销原因必填，上限 500，前后端一致。
- 新增请求幂等键及唯一约束，相同请求重试返回原 ID，不同内容复用同一键拒绝；提交携带预期持有关系版本，陈旧表单要求刷新。
- 为资产持有关系增加单调版本；所有会改变持有人、有效领用或资产状态的相关写入路径同步推进。登记、归还、签署、撤销使用一致锁顺序：来源单按 ID 排序 → 资产 → 调拨记录；锁后重新校验关联关系，显式更新字段并检查受影响行数。
- 撤销仅允许最新完成调拨，且资产、承接记录和版本仍与生效时一致，没有后续调拨／交接／借还／签收；否则拒绝并解释。撤销事务恢复原领用状态、持有人、部门、有效领用和领用日期，终止承接记录后再标记调拨取消。
- 撤销原因、操作人、时间独立保存，不覆盖原备注；缺失原来源或员工不能默认把资产释放为闲置。旧记录缺少安全回滚快照时只读，提示人工核查。
- Schema 变更使用新的增量 SQL 和 `EamSchemaMigrationInitializer` 版本，支持重复执行；不修改已执行迁移，不自动修补有歧义的历史责任数据。

## 权限与异常
- 统一调拨相关路由归属 `asset-transfer-list`：查看依赖 `view`，登记／撤销依赖 `edit`；普通员工不会因角色名称而自动获得操作权限。
- 在调拨域提供受同菜单授权的候选资产、必要资产详情及部门／分类／品牌／员工选项接口，底层复用现有服务和数据源，仅返回办理所需字段。不给角色附送台账、组织或基础资料管理权限。
- 共享资产详情在调拨上下文使用对应受保护接口；编辑、标签绑定等其他菜单操作仍按原权限判断。URL 的 `from` 只负责导航，不构成授权。
- 前端隐藏无权操作，后端仍逐接口校验；管理员、调拨只读、调拨可编辑但无其他菜单权限、完全无权限四类均测试。
- 请求统一经过 `request`；业务页不重复弹 API 错误。补齐加载、空态、失败重试和冲突提示，选项加载失败不退回假数据。

## 后续建议（不纳入本次实现）
- 审批流与接收确认：高价值或跨部门资产需要事前授权时再引入，避免把直接登记误称申请审批。
- 批量调拨：提供逐资产资格检查及失败明细，适合部门搬迁场景。
- 附件／资产照片／调入位置：提供交付状态凭据；位置只有实际搬迁才修改。
- 历史追溯与导出：按资产串联领用、调拨、归还及撤销记录，导出增加独立权限和范围限制。
- 借用责任转移：如确有需求，另行设计原借用人解除、接收人确认、到期日继承及逾期责任规则，不复用普通调拨直接换人。
