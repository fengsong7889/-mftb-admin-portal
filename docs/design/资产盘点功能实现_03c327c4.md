# 资产盘点功能新版执行方案

## 1. 目标、已确认决策与实施边界

本方案替代原计划。当前仅供确认，不开始编码、数据库迁移、服务重启、提交或部署。

### 已确认的业务决策
| 项目 | 实施规则 |
|---|---|
| 盘点作用 | 形成核对记录及差异报告，不自动创建遗失、维修、报废、调拨、交接等单据 |
| 应盘范围 | 发起时选择范围，生成固定应盘清单 |
| 核对内容 | 实物存在性、完好性、实际位置、实际持有人与账面差异 |
| 提前结束 | 允许部分完成，必须填写原因；未盘不能算缺失 |
| 页面形态 | 列表、发起、详情/执行三个独立页面视图 |

### 第一期不做
- 未登记实物盘盈、范围外资产补录、自动调整台账、OA 审批、手机扫码、通知催办、定时任务。
- 已结束任务重新打开、删除报告、修改发起范围。需要重新盘点时创建新任务。
- 对其他资产运营菜单进行顺带重构或修复。

### 数据写入边界
- 只写盘点任务、盘点明细及盘点操作日志。
- 台账、员工、部门、仓库、分类、品牌、相关运营单据只读。
- 不改变资产状态、使用人、仓库、领用/借用关系、`holdVersion`；不因盘点锁住正常资产业务。
- 报告明确提示：差异尚未构成报失、维修或调拨处置，后续由有相应菜单权限的人员另行办理。

## 2. 业务规则

### 2.1 发起范围与预览
- 范围模式必须显式选择「按條件盤點」或「全部適用資產」，默认按条件，至少选择一项条件，防止漏填变成全盘。
- 条件：存放仓库多选、资产分类多选、资产归属部门单选、所属品牌单选、资产状态多选。
- 所属品牌使用 `companyBrand`，不是产品品牌 `brand/brandId`。
- 部门条件匹配 `asset.department`，界面标明「資產歸屬部門」，不混用 `adminDepartment` 或员工当前组织。
- 同一维度多选取 OR，不同维度取 AND；仓库、分类、部门选择父节点时包含子节点，展开后去重。
- 分类仅使用 ASSET 业务类型；部门 ID 由后端解析为现有台账中的名称集合，名称存在歧义时拒绝创建并说明原因。
- 范围选项不存在、非法或已不允许选择时直接报错；禁止过滤条件失效后静默扩大范围。
- 先调用专用预览接口，返回应盘总数、状态分布、分页样例和范围指纹；不通过普通台账分页条数推断总数。
- 创建时用同一查询构造器重算范围指纹；资产或范围资料变化导致指纹不一致时，要求刷新预览并重新确认，不自动接受变化后的清单。
- 应盘数为零禁止创建。范围模式、原始条件、展开后的 ID/名称集合均保存为范围快照。

### 2.2 状态适用范围
| 台账状态 | 新任务规则 |
|---|---|
| `idle` 闲置、`in_use` 在用 | 默认包含；在用资产可以现场核实或通过持有人核实 |
| `in_repair` 维修中 | 默认包含，显示维修背景；送修不等于盘点缺失 |
| `pending_inspection` 找回待验收 | 默认包含，显示待验收背景；盘点不替代验收 |
| `lost` 已登记遗失 | 默认不选，可显式纳入专项核对；标记「帳面已遺失」，不重复暗示新发生遗失 |
| `scrapped` 已报废、`written_off` 已核销、已删除 | 不纳入新任务 |

- 发起后不自动增删应盘资产。期间入库、调出、归还、报失、报废或删除等变动另行提示。
- 快照缺少姓名、仓库等资料时保留缺失状态，禁止伪造历史值。

### 2.3 每项资产核对内容
- 实物结果继续沿用内部值 `pending/normal/lost/damaged`，界面分别为「未確認／實物完好／未找到／實物損壞」；`lost` 仅为盘点观察，不是台账状态变更。
- 找到实物时核对实际位置：选择现有仓库，或者选择「其他位置」填写具体位置；支持尚未确认，不强迫乱填。
- 找到实物时核对实际持有人：员工、无人持有、外部保管三种；员工使用真实 ID 选择，外部保管填写名称。未查明时保持待确认。
- 位置、持有人结果由后端依据实际输入和发起快照计算为一致、差异、待确认；未找到时这两个维度标为不适用，不把空值算成差异。
- 位置优先按仓库 ID 比较，旧账面只有文本时进行规范化后的精确比较；未知值不能自动判一致。
- 员工按 ID 比较，姓名和工号只作展示快照；账面姓名有值但身份 ID 缺失时标记资料待核查，不按同名自动判一致。
- 一件资产可以同时存在损坏、位置差异、持有人差异，不能互相覆盖。
- 缺失、损坏、位置/持有人差异需要填写说明；记录核对方式「現場核對／持有人確認／單據佐證」及核对时间。照片上传留后续版本。
- 核对时间默认服务器当前时间，可填写本任务发起后的实际核对时间，不得晚于当前时间。
- 支持逐行保存未完成核对内容；刷新后保留已保存字段。仅保存备注不改变原核对时间。
- 重置为未确认需明确操作并记录原因，清除该次实际结果，原值保留在操作日志中。

### 2.4 期间业务流转与快照
- 明细保存三类资料：发起时账面快照、实际核对记录、核对时的当前台账快照。
- 界面区分「發起時帳面」「實際核對」「當前台賬」，不得拿当前台账回填历史快照。
- 台账状态、位置、持有人或有效持有关系在已核对后变化时，显示「期間業務變更，待復核」；仅图片、备注等无关变化不要求重盘。
- 版本用于发现变更，最终按关键业务字段比较，避免任意 `holdVersion` 递增造成无意义重核。
- 核对保存携带看到的台账关键字段指纹；后端发现过期则要求刷新，拒绝旧页面无提示覆盖。
- 操作人可复核新情况并更新实测记录，差异说明必须记录正常业务流转依据；发起快照不覆盖。
- 完成预检查展示尚未核对和待复核资产；最终结束再次校验任务版本和台账比对指纹。
- 已结束报告保存结束时台账比对快照和比对时间。之后业务变化不改变历史报告；实时台账只能作为明确标记的独立参考信息。
- 全过程只读台账，不获取长期资产锁；报告说明其数据基准是记录的快照时间，而非永久实时状态。

### 2.5 统计口径
- 应盘数：发起时固定清单数量。
- 已核对数：实物结果已确认，且适用的位置/持有人维度已确认、期间变更已复核的资产数量。
- 未完成核对数：应盘数减已核对数；拆分为尚未核对与期间变更待复核，不能计作缺失。
- 实物确认数：实物完好及实物损坏数量；与已核对数不同，位置尚未确认时也可以确认实物存在。
- 分项异常：未找到、实物损坏、位置差异、持有人差异分别计数。
- 异常资产数：出现上述任一已确认异常的资产去重数量，不把分项数量简单相加。
- 对账面原已遗失/维修中的资产显示背景标签，不能直接将其解释为本期新增损失。
- 保留旧 `diff_count = actual_count - expected_count` 的含义；新 UI 主指标改为明确的已核对数、异常资产数、未完成核对数。
- 部分完成报告不把数量差额解释为盘亏，显示已确认缺失和剩余未核对数量。
- 统计结构化保存/聚合，不拼接到用户备注；列表、详情、结束确认、导出共用后端统计口径。

### 2.6 状态机和结束条件
```text
in_progress 進行中
  ├─ 全部核对完成 → completed 已完成
  ├─ 有已保存核对记录且仍有未完成项 + 原因 → partially_completed 部分完成
  └─ 取消原因 → cancelled 已取消
```
- 完整完成必须未完成核对数为零，后端强校验。
- 部分完成必须未完成数大于零、有至少一项实质核对记录且填写原因；全部未核对时只能继续或取消，不能产生空的部分完成报告。
- 结束方式必须由用户在确认框中明确选择，不静默从完整完成降级为部分完成。
- 已完成、部分完成、已取消均只读，不再保存核对结果；取消保留已保存结果和操作记录。
- 发起日期、核对时间、结束时间分开记录，支持跨日盘点。

## 3. 页面与交互

### 3.1 任务列表
- 路由仍为 `/asset-inventory`；独立发起页 `?create=1`，详情/执行页 `?id=任务ID`。
- URL 为视图来源，覆盖直接访问、刷新、前进后退、非法 ID 和不存在任务。
- 搜索：任务编号/名称、负责人、任务状态、发起日期区间。
- 列：编号、名称、范围摘要、负责人姓名（工号）、应盘数、已核对数、异常资产数、未完成数、状态、发起/结束时间、最后更新人、操作。
- 操作：进行中可核对/取消；已完成及部分完成查看报告；已取消查看记录。
- 使用 `useColumnConfig`、统一查询/重置区、完整分页控件。导出按钮为绿色描边并受权限控制。

### 3.2 发起页
- 基础信息：任务名称、盘点负责人、备注；负责人不是系统操作人，可由有盘点操作权限的用户代为登记。
- 范围模块：模式、仓库、部门、分类、所属品牌、状态；各维度及全盘影响清晰提示。
- 预览模块：数量、状态分布、分页资产清单；范围改变后旧预览失效，重新预览前不可发起。
- 表单校验 → `custom-confirm-modal` 展示负责人、范围及应盘数 → 创建 → 跳转执行页。

### 3.3 详情/执行页
- 顶部任务信息与状态；四张主统计卡：应盘、已核对、异常资产、未完成核对，分项统计在明细区展示。
- 明细支持编号/名称、核对进度、异常类型、仓库筛选及后端分页；提供账面与实际值对照。
- 行内/展开行编辑实物结果、实际位置、实际持有人、核对方式、时间、说明；不另开新增/编辑 Modal。
- 暂存反馈区分保存中、成功、失败；失败保留本地输入；未保存或保存中不能结束任务，离页提醒。
- 批量核对仅作用于当前页显式勾选且尚无已保存核对结果的资产，最多 100 项；切换筛选/分页清空选择，不提供「全部未盘直接正常」。
- 批量确认文案为「確認所選資產實物完好，位置及持有人均與發起時帳面一致」。账面缺资料、已有核对、存在期间变更的行不可使用此快捷操作，改用逐项核对。
- 完整完成/部分完成均先预检查、再二次确认；确认框展示异常去重数、各分项数量、未完成数及结束原因。
- 已结束只读，部分完成有醒目标识；可分别导出全量清单、差异清单、未完成清单；取消任务导出标识为记录，不称完整报告。

### 3.4 全站规范
- 遵循 `form-page-style.md`：编辑态橙色渐变头部、白色 div 模块卡、底部 `.form-footer`；只读详情无保存操作栏。
- 部门使用 TreeSelect 和 `buildDeptTree`；仓库展示「仓库名（城市区县详细地址）」。
- 员工下拉和表格持续显示姓名（工号），从原始字段构建标签，不反解析 label。
- 所属品牌选项来自现有品牌配置体系，展示复用 `BrandTag`；报告同时保存名称快照。
- 文案走 zh-TW/en 双语资源，中文界面使用繁体；统一状态常量、请求实例及错误拦截，不重复弹错误。
- 数据指标卡遵循现有四格动效规范；列表和明细分别配置列，不复制独立列配置实现。

## 4. 后端与数据模型

### 4.1 在现有表上增量扩展
不另建第二套盘点主表。保留 `biz_eam_inventory_task/item`，增加操作日志表。

| 位置 | 新增/明确的数据 |
|---|---|
| 任务表 | `contract_version`、范围 JSON（ID 数组与名称快照）、快照时间、负责人 ID/工号/姓名、创建人 ID/工号、任务 revision、结构化统计、结束方式/原因/时间/操作人、取消信息、创建请求键及摘要 |
| 明细表 | 契约版本、账面快照 JSON（状态、持有方式、仓库、分类、品牌、资产归属/管理部门、持有人 ID/姓名/工号、活跃持有关系、版本）、实测位置/持有人字段及确认状态、差异标记、核对方式/时间/操作人、核对时/结束时台账快照、复核信息、明细 revision |
| 操作日志表 | taskId、可空 itemId、动作、请求键/摘要、前后值 JSON、原因、登录操作人 ID/姓名/工号、时间；覆盖创建、保存、批量、重置、完整/部分完成、取消 |

- 常用筛选和统计字段使用独立列；JSON 用于不可变快照，不保存图片大字段。
- 员工身份由后端按 ID 验证并写入姓名、工号；新选择负责人及实际持有员工须在职可用，历史快照不因离职失效。
- 任务名称限 200 字，备注及异常/结束原因限 500 字；所有枚举、ID、日期、数组大小在后端校验。
- 新版明细保证 `(task_id, asset_id)` 唯一；为保留可能重复的旧明细，采用仅新版行生效的条件唯一索引（MySQL 生成列）；旧记录不删除、不合并。
- 创建请求唯一键为 `(创建用户ID, requestKey)`；变更日志唯一键为 `(taskId, requestKey)`。相同键同一请求返回既有结果，不同内容拒绝。
- 任务状态/时间、明细 taskId/进度/异常类型等建立所需索引。

### 4.2 事务和并发
- 修改统一顺序：锁任务行 → 按 ID 顺序锁涉及明细 → 检查归属/状态/版本 → 写结果和日志 → 重算统计 → 递增任务 revision → 提交事务。
- 不锁资产行；资产读取只用于快照和冲突提示，不参与资产状态更新。
- 单行采用明细 revision 校验，允许不同明细分别更新；同一明细过期提交返回冲突，不采用最后写入覆盖。
- 批量原子提交，任一行不符合条件全部回滚并返回问题行，不静默跳过。
- 完成/取消/保存走同一任务锁；结束事务重新检查未完成数与期间变化，不允许结束后迟到请求改变报告。
- 完成预检查返回任务 revision 和台账比对指纹；正式完成不一致时重新预检查，用户再次确认。
- 任务统计在锁内使用条件聚合，避免 Java 全量反复扫描和列表 N+1 查询；前端忽略旧 revision 的迟到统计响应。

### 4.3 接口契约
新版接口放在 `/api/eam/inventory/v2`，复用现有 Controller/Service 领域实现，旧路径仅作兼容读取。

| 方法/路径 | 职责 | 权限 |
|---|---|---|
| GET `/tasks` | 任务分页、编号/名称/负责人/状态/发起日期筛选 | view |
| GET `/tasks/{id}` | 任务头、全任务统计、报告元数据 | view |
| GET `/tasks/{id}/items` | 明细分页、核对进度及异常筛选 | view |
| GET `/tasks/{id}/events` | 操作记录分页 | view |
| GET `/options`、GET `/employees` | 最小化仓库/分类/部门选项、在职员工搜索 | create |
| POST `/preview` | 按同一范围逻辑预览和生成指纹 | create |
| POST `/tasks` | 创建，返回 `{id, taskNo}` | create |
| PUT `/tasks/{id}/items/{itemId}` | 保存/重置明细，含版本和请求键 | create |
| POST `/tasks/{id}/items/batch-check` | 显式选中项的批量核对 | create |
| POST `/tasks/{id}/prepare-close` | 结束预检查 | create |
| POST `/tasks/{id}/complete` | 完整/部分完成，必带结束方式 | create |
| POST `/tasks/{id}/cancel` | 取消，原因必填 | create |
| GET `/tasks/export`、GET `/tasks/{id}/export` | 任务列表/指定任务报告导出 | export |

- 权限统一绑定 `asset-inventory`，不要求员工管理、组织管理、仓库维护等无关菜单权限；不得降低那些管理接口的原权限。
- `create` 继续表示盘点写操作，前端说明调整为「盤點操作」，不更改既有角色授权；指定负责人不构成额外权限授予。
- 专用选项只返回选择所需字段；复用底层业务查询，不调用要求其他菜单权限的 Controller。
- 部门前端兼容既有 TreeSelect 规范：为 `fetchDepartments` 增加可选盘点来源参数，默认行为不变；盘点来源使用新版选项并规范化为树所需最小字段。`buildDeptTree` 入参收窄为实际所需字段，兼容既有调用方。

### 4.4 导出
- 后端校验 export 权限，输出 UTF-8 BOM CSV，不以当前页数据或超大 pageSize 代替全量导出。
- 任务列表导出当前筛选条件下所有任务；报告导出指定任务全部匹配明细，按全量/异常/未完成三个模式选择。
- 每份报告携带编号、范围、数据基准时间、状态、负责人、结束原因及统计口径；部分完成和旧版报告明确标识。
- 使用只读一致性视图及分批读取；进行中导出标为临时记录，不冻结任务、不保存新业务状态。
- 对编号、姓名、备注等文本做 CSV 引号转义和公式前缀防护，防止 Excel 执行以 `= + - @` 等开头的文本；数量型列保持真实数值。

## 5. 旧数据与发布兼容

- 旧任务标记 `contract_version=1`，新任务为 2；旧统计和历史结果保留，不重新计算覆盖。
- 旧已完成任务显示「歷史盤點紀錄」；即使含 pending 也不伪装成新版完整核对报告，缺少的新字段显示「歷史未記錄」。
- 旧进行中任务只允许查看/导出/填写原因取消，不凭当前资产数据伪造发起快照；需要继续作业时重新创建新版任务。
- 旧读取接口继续可读旧任务；旧创建/提交/取消写接口停用并明确提示刷新进入新版，不能保留旧提交路径绕过校验。
- 新前端不得在新版接口不可用时退回旧写逻辑；提示后端版本未就绪。
- 后端先具备新版能力再切换前端；正式发布另行获得授权，本轮及后续本地实现不自动部署。
- MySQL 增量迁移使用 INFORMATION_SCHEMA 检查、`applyOnce` 和前后日志，不修改已执行的 v11 定义冒充新迁移。
- 当前拟用 `backend/sql/184_eam_inventory_v2.sql` 和 `eam:schema-v33-inventory-v2`；执行前查重，若其他任务占用则按实时最大序号顺延。
- 新列允许历史为空，旧行按版本区分；不得 DROP/TRUNCATE，不删除重复历史数据。

## 8. 测试与验收门槛

### 后端测试
- 范围多选、父子展开、AND/OR、品牌区分、部门同名拒绝、失效条件不扩大范围、空清单、预览创建之间数据变化。
- 默认状态覆盖与已核销/报废排除；已遗失显式纳入并正确标识。
- 实物、位置、持有人三个维度组合；一资产多异常去重；待确认不算缺失。
- 在用、借用、维修、找回待验收及期间调拨/归还/报废/删除，快照保留且提示正确。
- 全部未盘不能部分完成；部分完成原因必填；完整完成必须全部核对；结束后不可修改。
- 同一行并发、不同明细并发、保存与取消/完成并发、重复请求、跨任务 itemId、批量部分非法全部回滚。
- 旧记录不补造历史、不改旧统计；旧写接口不能绕过新版；超过 200 条导出完整、CSV 特殊字符及公式前缀处理。
- 验证所有盘点写操作均未调用资产/领用/借用/遗失/维修/报废更新，台账状态与 `holdVersion` 不变。

### 前端与联调
- 仅有盘点权限的账号能够加载负责人/范围；只读账号无写入口、接口拒绝写入；无 export 权限不能下载。
- 名称与工号选中后持续回显；仓库地址完整；部门树与所属品牌一致；进度和分项差异数量正确。
- 页面刷新、前进后退、切换任务、过期请求、保存失败、保存中结束、未保存离页。
- 显式勾选批量操作不影响隐藏页；有差异的任务能够保存并生成报告，其他业务数据不变。
- 完整完成、部分完成、取消、旧版历史四种详情与导出标识正确。

### 执行命令
- 前端：`npm run typecheck`、`npm run lint`、`npm run test:run`、`npm run build:strict`。
- 后端：`mvn -f backend/pom.xml compile -q`、`mvn -f backend/pom.xml test -B`；并发/迁移验证在隔离 MySQL 8 开发测试环境完成，不能仅依赖 Mock 单测证明事务安全。

- 验证失败先定位并处理；存量或环境问题明确记录，不把未执行或未通过写成通过。

## 9. 最终验收定义

用户能够按指定范围发起盘点，持续保存实物、位置和持有人核对结果；正常资产业务照常流转且有变化提示；可选择完整完成或注明原因部分完成；报告可追溯、可导出且不会把未盘当盘亏；整个盘点过程不改变其他资产运营数据。
