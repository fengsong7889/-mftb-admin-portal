# 用户端 APP 搜索体验设计（2026-10-26）

> 范围：企业门户 →「移動 APP」→ 用戶端。覆盖首页全站搜索、美食外賣、特價團購、超市百貨、店内搜索 5 类搜索。
> 结论已落地到 `/app-preview?app=consumer` 原型（纯前端 Mock，不涉及后端与数据库变更）。

## 1. 背景与目标

现状 5 个入口的搜索框都是静态占位，无法输入、无结果页；「超市百貨」页与「店鋪詳情頁」尚未建立，因此第 4、5 类搜索没有承载页面。

本次要解决三件事：

1. **框架统一**：5 个入口共用一套「搜索激活页 → 联想 → 结果页 → 空态」结构，降低学习与维护成本。
2. **作用域隔离**：首页全站搜（外卖 + 团购 + 超市），频道页只搜本频道，店铺页只搜本店，避免跨频道噪声。
3. **信息维度可比**：结果卡片只展示能帮助用户「快速比较并决策」的字段，不把详情页信息堆到列表。

成功标准（原型可验收）：

- 任一入口点击搜索框进入搜索页，输入关键词能得到**符合当前作用域**的店铺 / 商品 / 套餐结果。
- 首页搜「紙巾」能命中超市商品；外卖页搜「紙巾」无结果并给出「在全站搜尋」出口。
- 店铺页有独立的「搜尋店內商品」入口，结果不串到其它店铺。
- 搜索历史按作用域隔离、可清空；非全局作用域空态可一键升级为全站搜索。

## 2. 竞品调研结论

调研对象：美团 / 美团外卖、饿了么、京东，辅以淘宝、拼多多、微信、知乎的搜索模式。

| 维度 | 美团 / 美团外卖 | 饿了么 | 京东 | 可借鉴结论 |
|---|---|---|---|---|
| 搜索前（激活页） | 搜索框底纹词、搜索历史、热搜榜、猜你想搜 | 历史 + 搜索发现 + 热搜 | 历史、发现、今日热榜；搜索组件随页滚动 | 激活页必须有「历史 / 热搜 / 猜你想搜」三件套；底纹词承担引导，不承担状态 |
| 输入中（联想） | 关键词高亮、店铺/商品混排、可直接点选 | 词条联想 + 分类联想 | 联想词按商品/店铺分组 | 联想要带**类型标签**与少量结果元信息（店铺评分、商品价格），帮用户预判结果 |
| 结果组织 | 按业务线 Tab（全部/外卖/团购…），商家卡为主 | 商家/商品分类 + 多种排序 | 双滚动 Tab 筛选；商品 Tab 支持快速筛选标签 | 全局搜索先按**业务线**分 Tab；频道内再按**店铺/商品**分 Tab；不要把所有类型混成一条流 |
| 商家卡维度 | 评分、月售、配送时长、距离、起送价、配送费、优惠、营业状态 | 评分、起送价、销量、送餐速度、距离 | 店铺评分、商品数、促销、服务标签 | 外卖/超市商家卡六件套：**评分 + 月售 + 时效 + 距离 + 履约门槛 + 优惠** |
| 商品卡维度 | 商品图、名称、价格、划线价、月售、所属店铺 | 价格、销量、店铺、配送 | 价格、促销、评价数、店铺、物流服务 | 商品卡要回答「多少钱、哪家店、卖得怎样、有什么优惠」 |
| 排序 | 综合、距离、销量、配送费、筛选 | 热门、评价星级、起送价、销量、送餐速度、距离 | 综合、销量、新品、价格、配送、筛选 | 排序项按频道取舍；外卖/超市保留**距离/销量/配送费**，团购保留**销量/距离/价格** |
| 店内搜索 | 店铺页顶部「搜索店内商品」，按店内分类过滤 | 店铺页搜索只搜本店 SKU | 店铺内搜索 + 店内分类 | 店内搜索必须限定本店，并提供分类 chips 与「查看全部商品」兜底 |

关键结论：

1. **搜索是三层结构，不是单个输入框**：搜前引导（历史/热搜/猜你想搜）→ 搜中联想 → 搜后结果与筛选。缺一层，用户就会在空输入框前流失。
2. **作用域必须显性化**：在搜索页顶部用标签写明「全站 / 外賣 / 團購 / 超市 / 店內 · 店名」，否则用户无法理解为什么搜不到隔壁频道的东西。
3. **结果先分类目再排优劣**：先让用户选对「店铺还是商品 / 哪个频道」，再谈排序与筛选；顺序反了，筛选器再全也救不回来。
4. **空态是二次分发入口**：频道内搜不到时，提供「在全站搜尋」比只显示「暂无结果」更有价值。
5. **店内搜索是独立闭环**：只搜本店、按店内分类组织、结果可直接加购；不能复用全局搜索结果页的频道 Tab。
6. **隐私与可清除**：搜索历史本地存储、按作用域隔离、支持一键清空，符合主流电商的隐私预期。

## 3. 统一搜索框架

```
入口（各页搜索框，带作用域底纹）
  └─ 搜索激活页
       ├─ 作用域标签：全站 / 外賣 / 團購 / 超市 / 店內 · 店名
       ├─ 搜尋歷史（按作用域隔离，最多 10 条，可清空）
       ├─ 熱搜榜（按作用域配置，前三名高亮）
       └─ 猜你想搜 / 店內分類（店内态）
  └─ 输入中：联想面板（首行「搜尋『关键词』」+ 分组联想）
  └─ 提交后：结果页
       ├─ 结果摘要（命中数 + 关键词）
       ├─ 作用域内 Tab（带计数）
       ├─ 排序行 + 篩選 chips
       ├─ 综合态：店铺区 + 商品/套餐区
       └─ 空态：改词建议 + 全站搜尋出口 + 热搜
```

### 3.1 搜索前：激活页

- 输入框自动聚焦；右侧固定「取消」。
- 作用域标签必须出现；店内侧显示店名并允许返回店铺。
- 历史为空时显示轻提示，不渲染空标题；历史只存本地，最多 10 条，同一关键词去重前置。
- 热搜按作用域配置，前三名用品牌橙序号；不展示与当前作用域无关的词。
- 店内侧额外展示「店內分類」chips（来自本店商品分类），点击即按分类过滤。

### 3.2 搜索中：联想

- 首行固定为「搜尋『输入词』」，保证任何输入都有提交出口。
- 联想按类型分组：店鋪 / 商品 / 團購套餐 / 分類；每行带类型标签。
- 关键词命中部分高亮；店铺联想带评分，商品联想带价格，套餐联想带店铺名。
- 最多 8 条；空输入不展示联想。
- 输入变化但未提交时展示联想，提交后展示结果；清空输入回到激活页。

### 3.3 搜索后：结果页

- 顶部搜索框吸顶，保留关键词与清除按钮。
- Tab 计数反映当前关键词与筛选条件下的可命中数；切 Tab 不重新请求（原型内即时计算）。
- 排序与筛选放在 Tab 下方一行；「篩選」展开为 chips 行，不弹全屏抽屉（首版保持轻量）。
- 综合态分组：先「店鋪」，后「商品與團購」；每组有标题与数量，避免一条流里店铺/商品反复横跳。
- 卡片点击：商家卡/商品卡都进入对应店铺页；店内搜索结果可直接加购。

## 4. 五类搜索作用域

| 作用域 | 入口 | 可搜对象 | Tab | 排序 | 筛选 chips | 特殊规则 |
|---|---|---|---|---|---|---|
| 全站 `global` | 首页搜索框 | 外卖、团购、超市的商家 + 商品 + 套餐 | 綜合 / 外賣 / 團購 / 超市 | 綜合、距離、銷量、篩選 | 免配送費、優惠、營業中、隨時退、神會員 | 卡片带频道角标；空态可切换到全站（已是全站则只给改词建议） |
| 美食外賣 `delivery` | 外卖页搜索框 | 仅外卖商家 + 外卖商品 | 綜合 / 商家 / 商品 | 綜合、距離、銷量、配送費、篩選 | 免配送費、優惠、營業中、可自取 | 空态提供「在全站搜尋」；商家卡强调配送时效/距离/配送费 |
| 特價團購 `groupbuy` | 团购页搜索框 | 仅团购套餐 + 团购商家 | 綜合 / 團購套餐 / 商家 | 綜合、銷量、距離、價格、篩選 | 隨時退、折扣、到店可用 | 套餐卡强调团购价/原价/折扣/半年售；无配送字段 |
| 超市百貨 `market` | 超市页搜索框 | 仅超市商家 + 超市商品 | 綜合 / 商家 / 商品 | 綜合、距離、銷量、價格、篩選 | 免配送費、優惠、營業中、可自取 | 商品卡必须有规格（如 250ml×6）；商家卡强调起送价/配送费 |
| 店內 `store` | 店铺页搜索框 | 仅本店商品（团购店为套餐） | 无 Tab（单一结果列表）+ 分類 chips | 綜合、銷量、價格 | 優惠 | 不出现跨店结果；空态给「查看全部商品」；结果可直接加购 |

## 5. 卡片信息维度（唯一口径）

### 5.1 商家卡

| 字段 | 外卖 | 团购 | 超市 | 说明 |
|---|---|---|---|---|
| 店铺图 / 店名（关键词高亮） | ✓ | ✓ | ✓ | 名称命中优先展示 |
| 频道角标 | 全局搜索时显示 | 同左 | 同左 | 仅 `global` 作用域 |
| 评分 + 月售 | ✓ | ✓ + 团购数 | ✓ | 评分用品牌橙 |
| 配送时长 + 距离 + 配送费 + 起送价 | ✓ | — | ✓ | 履约六件套，缺一不可 |
| 距离 + 人均/团购数 | — | ✓ | — | 团购无配送概念 |
| 优惠 / 券标签 | ✓ | ✓ | ✓ | 最多 3 个，超出折叠 |
| 状态标签（新店/休息中/可自取） | ✓ | ✓ | ✓ | 休息中置灰并压暗卡片 |

### 5.2 商品卡

商品图、名称（高亮）、规格、所属店铺 + 频道、现价、划线价、折扣/券后标签、月售、加购按钮（仅店内侧）。

### 5.3 团购套餐卡

套餐图、标题（高亮）、店铺名 + 距离 + 评分、团购价/原价/折扣、半年售、随时退/免预约/到店可用标签。

> 约束：搜索结果不引入详情页独有字段（如营业时间、完整地址、菜单结构）。列表只保留「可比较」字段；需要更多信息时进入店铺页。

## 6. 状态设计

| 状态 | 触发 | 表现 |
|---|---|---|
| 无历史 | 首次使用 / 已清空 | 历史区显示「還沒有搜尋記錄」；热搜与猜你想搜照常 |
| 输入中 | 输入非空且未提交 | 联想面板；首行固定「搜尋『词』」 |
| 有结果 | 提交后有命中 | 摘要 + Tab 计数 + 分组列表 |
| 无结果 | 提交后 0 命中 | 🔍 图标 + 「沒有找到與『词』相關的結果」+ 改词建议 + 全站出口（非全局）+ 热搜 |
| 加载中 | 请求中（生产） | 结果区骨架屏，保留搜索框与 Tab；不使用整页 spinner |
| 失败 | 请求失败（生产） | 结果区错误卡 + 「重試」；保留关键词，允许改词 |
| 无结果且切换 Tab | 某 Tab 为 0 | Tab 显示 0 并置灰；不自动跳 Tab，避免用户失去位置感 |

## 7. 接口契约建议（生产接入时）

```http
GET /api/mobile/search
  ?scope=global|delivery|groupbuy|market|store
  &storeId=<店铺 ID，scope=store 必填>
  &keyword=<关键词>
  &tab=all|merchant|product|deal|delivery|groupbuy|market
  &sort=default|distance|sales|price_asc|price_desc
  &filters=free_delivery,discount,open,pickup,refundable,member
  &page=1&pageSize=20
```

响应至少包含：

```json
{
  "keyword": "檸檬茶",
  "scope": "global",
  "counts": { "all": 12, "delivery": 7, "groupbuy": 1, "market": 4 },
  "sections": [
    { "key": "merchant", "title": "店鋪", "items": [] },
    { "key": "offer", "title": "商品與團購", "items": [] }
  ],
  "hotWords": ["..."],
  "suggestions": ["..."]
}
```

- 联想、热搜可拆为 `GET /api/mobile/search/suggest` 与 `/hot`；首版允许与搜索同源返回，减少首屏请求数。
- 搜索历史默认存本地；若后续做跨端同步，再引入服务端历史，不改变前端交互。
- 埋点：`search_enter`、`search_submit`、`suggest_click`、`tab_switch`、`filter_apply`、`result_click`、`search_empty`，均带 `scope` 与 `keyword`（脱敏后）。
