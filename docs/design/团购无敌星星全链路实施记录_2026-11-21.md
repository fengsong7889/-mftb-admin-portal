| # | 决策 | 口径 |

| D1 | 瀑布流坑位约束 | 只约束星星匹配维度：商品维度只能绑商品星星；门店维度可绑门店星星＋投流等其他门店型算法 |

## 3. 各阶段实施要点

### P1 瀑布流策略
- 后端：`AdWaterfallRequest/VO/ServiceImpl` 支持业务线/维度/内容来源/类目兜底/固定坑位；列表 `businessType` 分页前过滤；`validateSlots` 维度感知（`AdStarAlgorithmParams.requireWaterfallDimension`）：商品维度只放商品星星且必须配商品类目兜底、禁自然兜底；门店维度拒绝商品星星、其余照旧；外卖链路校验语义不变。
- 前端：团购保存全量走服务端（不再写 localStorage 策略），升级前本地草稿在保存成功后清理；商品维度算法候选显式 `algoType=1&businessType=2&targetType=2`；`WaterfallBinding` 按 D4 精简；`waterfallExtStore` 读取优先级=扩展（存量）→后端字段→频道推断。

### P2 销售定价
- 后端：商品星星仅开放 channel=4 定价；商品定价服务端强制 `sellTimeSlots=['fullDay']`、拒 `discountTiers`、拒餐段折扣键（前端隐藏只是 UX，服务端是边界）；保存快照 `target_type`。
- 前端：`WaterfallAdd` 团购星星新增「推廣對象」切换（编辑/详情锁定，由 `target_type` 回填）；商品变体隐藏可售时段/多时段梯度折扣/餐段折扣，商圈表改为全日单价；定价列表商品星星加「商品」Tag。

### P3+P4 销售界面与推广金购买
- 新增 `src/pages/AdSales/StarProductPurchase.tsx`：品牌→商品星星算法→商品远程搜索（选项带归属集团），商圈×日期全天格子加购（60s 加购锁复用 lock/unlock，超时自动释放、卸载释放），推广金余额展示与下单扣款；门店维度继续复用外卖 `DateTimeGrid`（channel=4）。
- 后端 `AdSalesStarServiceImpl`：商品星星放行但仅团购频道；`productId` 商品必填/门店禁传；同商品同格有效订单防重（422）；格子价=日单价、只按全时段折扣；财务明细业务线标签按频道=团购记「團購」（此前硬编码「外賣」）。

### P5 订单与数据
- `AdOrderVO`/详情回传 `targetType/productId/productName`；`/ad/orders` 支持 `targetType/productId` 筛选（SQL 分页前）。
- 订单列表商品单「门店列」改显商品（名称+编码）；详情页商家区展示团购商品与「適用門店由團購業務系統決定」；时段标签 `fullDay`→「全天」；退款/取消沿用取消扣费梯度＋推广金回补（渠道标签同 P4 修正）。

## 4. 与外卖无敌星星的差异点（汇总）

1. 售卖粒度：商品=商圈×日期全天（`meal_slot='fullDay'`），无餐段/可售时段/多时段梯度折扣；门店=完全同外卖。
2. 购买对象：商品选购不选门店，选择团购商品（目录适配层），订单归属集团+商品。
3. 库存配额：格子配额（dailySalesLimit）语义为"该商圈该日可上架推广的商品数"，多商品共享同格；同商品同格禁重复有效订单。
4. 瀑布流：商品维度算法提供模式以商品类目兜底，不使用门店型自然流量算法。
5. 频道：商品星星定价/售卖仅 channel=4（团购到店）。

## 5. 例外登记（必须到期关闭）

**商品归属集团的真实校验（P4 下单链路）**
- 原因：团购商品目录当前为前端 Mock 适配层，后端无商品→集团归属真源。
- 现状：后端裁决 `productId` 格式（≤64）、`targetType` 从算法协议推导、`groupCode` 走既有推广金账户授权与屏蔽校验、同格防重；商品是否真属该集团依赖前端传入。
- 风险与补偿：Mock 数据仅自洽、不含真实商家；生产开放前必须接入 `GET /groupbuy/catalog/products` 并由服务端核验商品归属（不信任前端），同时 `productName` 快照改由服务端覆盖。
- 负责人：本模块实施者；到期：团购业务系统目录接口接入时。在此之前**不得开放生产售卖**。
