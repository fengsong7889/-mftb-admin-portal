## 批次 A：列表页返回不自动重取数 —— 【已验证不成立，无需修复】
- **结论**：经代码核验 + MF00002 浏览器实测，本症状不存在。
- **机制**：`App.tsx` 用 `<RouteErrorBoundary key={location.pathname}><Routes/></...>` 渲染页面，
  `MenuTabs` 只是上方持久的页签栏、**不缓存内容**；考勤列表(`/attendance-group`)与详情(`/attendance-group-detail`)
  是**不同 pathname**，返回时 key 变化 → 列表整树 unmount+remount → `useEffect` 重新 `GET /api/attendance/groups`。
- **实测**：成员数 1→2→3（详情页编辑保存 / 切页签返回 / 浏览器后退三条路径）列表覆盖人数均自动为最新值，无需手点查询；DOM 重建、返回时确有新的列表请求；控制台无 error/warn。
- **原报告的「旧值」实为 M3**：那是被烘焙进 `scope_text` 的静态快照（已随 D2/M3 提交消除计数内嵌），并非实时 `memberCount` 列陈旧。
- **残留细微点（观察项，非缺陷）**：remount key 取 `location.pathname` 不含 query，故「同一路径仅 query 变化」不 remount（如某些列表用 `?type=`/`?tab=` 切子视图）；这是常见且通常期望的行为，需要刷新数据的页面已按 query 参数在 `useEffect` 里重取。若将来某同路径多视图页出现陈旧，优先在该页监听 query 变化重取，而不是给全局 key 加 search（会让每次筛选都整树 remount，代价过大）。
