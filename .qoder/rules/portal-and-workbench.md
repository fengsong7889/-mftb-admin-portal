# 门户与工作台规范（强制）

版本：1.0 ｜ 状态：强制 ｜ 来源：《企业门户界面设计评审 2026-10-24》整改落地
上位规范：`.qoder/rules/frontend-ui-design-spec.md`（设计令牌 §A、§N 门户与工作台）
本文件是该章的可执行版：**改门户、加系统、做工作台之前必须逐条对照**。

## 0. 触发条件（命中任一必须读本文件）

- 修改 `src/pages/Portal/**`（含 `SystemArtwork.tsx`、`index.css`、`PortalTopBar.tsx`）
- **新增或下线业务系统**（门户会多/少一张卡）
- 新增首页工作台、看板、应用墙类页面
- 调整 `portal.*` 命名空间的语言包

## 1. 新增一个业务系统：必须完成的 7 件事

漏一项的后果写在括号里，别等 CI 红才回头查。

| # | 事项 | 位置 | 漏了会怎样 |
|---|---|---|---|
| 1 | 系统种子（code / name / icon / sort / status） | 后端 `sys_system` 种子 + 迁移登记 | 门户拿不到该系统的授权条目 |
| 2 | 编码归一化与别名 | `src/constants/portalSystems.ts` | 卡片匹配不到 scene，退化成通用插画 |
| 3 | 场景插画（新 scene key） | `SystemArtwork.tsx` 的 `scenes` / `variantScenes` | 同上，且与既有系统撞图 |
| 4 | 场景色 + 色板登记 | `index.css` 的 `[data-scene='x'] { color }` + 本文件 §3 表 | `Portal.test.tsx` 色调唯一性用例直接红 |
| 5 | 五语言名称与简介 | `portal.systems.<key>.name / .description`（zh-TW/en/ja/ko/ru） | 非中文界面回落中文 |
| 6 | 用例 | `Portal.test.tsx`：色调唯一、场景元素、五语言渲染 | 上述问题无人拦截 |
| 7 | 实拍验收 | 1600×1000：首屏卡片数、无裁切、可点击进系统 | 视觉缺陷靠用户发现 |

## 2. 插画六条铁律

1. **一卡一动作**：每张插画只讲一个动词（提交 / 对账 / 打卡 / 发布）。出现第二个动作就拆 `variantScenes`。
2. **元素预算 4 组**：主体 1 + 辅助 2 + 结果标记 1。超 4 组必然互相遮挡（财务卡、考勤卡都栽在这）。
3. **单色 + 一次品牌橙**：整卡只用该场景主色的明度阶（`currentColor` + `opacity .12/.3/.6/1`）。
   **品牌橙 `#E8720C` 每卡最多 1 次，且必须标记「结果/成功」**。装饰件、连线、齿轮一律 `currentColor`。
4. **文字 ≤ 2 处且走 i18n**：只允许「结果标签」「数值」；一律用 `ArtworkText`（走 `portal.artwork.*`）。
   禁硬编码英文短语。数学公式可留，但不得承载业务信息、不得与其它构件叠压。
5. **三段式构图**：左（输入）→ 中（处理）→ 右（结果），主体落在 `x≈120/320`，左右各留 ≥24px 安全区。
6. **留白 ≥ 25%**：密度不够就放大主体，不要加零件。

## 4. 动效节拍

- **主周期统一 6s**；慢镜头最多 1~2 个（当前仅 `rdm` 12s）。
- **分镜四段**：0–20% 输入入场 → 20–55% 处理发生（**大动作：≥8px 位移或 1.06 倍缩放或颜色跃迁**）→
  55–80% 结果落地（品牌橙完成态）→ 80–100% 静置呼吸。
- **播放策略两级**：入场自动播一次（首行 5 张，`mode='once'`，播完即停）；
  悬停只播微循环（`mode='loop'`，2.4s 重复），不逼用户等完整分镜。
- **错峰**：`[data-autoplay='1']:nth-child(n)` → `delay = (n-1)×0.35s`，**仅入场自动播期间生效**，悬停必须 0 延迟。
- **降级三条不得删**：离屏暂停（IntersectionObserver）、后台暂停（visibilitychange）、`prefers-reduced-motion` 全静态。
- **时序必须单线**：同一张卡任何时刻只能有**一条**叙事。教训：权限卡曾把「开门」放在 32%，与 18~36% 的「拒绝」重叠，
  用户看到的是「被拒绝了门却自己开了」。门的开合必须晚于「锁开」，且钥匙先拔出、门后关闭。

## 5. 版式

| 项 | 强制值 |
|---|---|
| 卡片墙栅格 | `repeat(auto-fill, minmax(min(280px, 100%), 1fr))`，间距 `16px` |
| 封面比例 | `320 / 140` |
| 卡片正文 | `padding: 14px 18px 16px`；简介 `min-height:36px; line-height:1.6` |
| 首屏目标 | 保持业务域分组时 **≥6 张**（实测 4 完整 + 2 部分）。「10 张」仅在统一卡片墙前提下成立，**不得为此取消分组** |
| 统计卡 | 允许上提叠横幅，但**左右各内缩 24px**，否则两层圆角打架、横幅露出橙色三角 |
| 分组标题 | 「图标 + 标题 + 计数」为唯一视觉单元；说明文字下沉第二行；装饰线 `max-width:24px` |
| 指标卡口径 | 统一「占比 + 绝对数」；`0` 要灰显并给微文案（如「全部已開通」），不能像故障 |

## 6. 「我的常用」（F1~F7）

- 星标**常显** `#BFBFBF`，悬停/聚焦升品牌橙；**禁止**用 `opacity:0` 仅靠 hover 显现（触屏直接失效）。
- 空态**照常渲染模块**，给虚线占位「還沒有常用系統 · 在卡片右上角點 ☆ 添加」。
- 计数口径 = **实际渲染条目数**（收藏 + 最近使用），不得只取收藏数。
- 双轨样式：收藏 = 业务域淡色**实底** + ×；最近使用 = **无底色 + 1px 描边**；两排间距 `8px`。
- 删除必须可撤销：× 仅 hover/聚焦显现，toast 带「撤銷」，`duration:5`。
- 超过 4 个单行限高 `max-height:38px` + 「+N 展開」；排序**最近添加在前**。
- 收藏相关配色用品牌橙 `#E8720C`/`#FFF7F0`，**禁止**借用警告色 `#FA8C16`/`#FAAD14`。

## 7. i18n 与失败态

- `portal.artwork.*` 键必须在 **5 个语言包**齐全（含新增/删除同步）；删渲染必须同时删键，
  否则 `Portal.test.tsx`（遍历全键断言渲染）会红。
- **禁止 `t(key, '中文兜底')` 新增双参写法**：`npm run check:i18n-fallback` 会把「key 不存在」判为阻断。
  新增文案走单参 `t(key)` 并补语言包。
- 失败态：页面级 `Empty + Retry` 已足够，`/portal/context` 走静默头**不要再弹 toast**；
  Tab 计数在加载失败时显示 `—` 而不是默认值 `0`。
- 超时文案走 `common.requestTimeout`（不得直出 `timeout of 15000ms exceeded`）。

## 8. 验证口径

改门户时的**最低有效门禁**（约 2 分钟）：

```bash
npx eslint src/pages/Portal                # 未使用变量、删除残留
NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit   # 默认 2GB 堆会 OOM
npm run check:i18n && npm run check:i18n-fallback
npx vitest run src/pages/Portal/Portal.test.tsx
```

提交/推送前**必须**再跑一次全量：

```bash
npm run verify    # lint + typecheck + 5 道门禁 + 全量 vitest
```

理由：`SystemArtwork.tsx` / `global.css` 的改动虽只服务门户，但 `tsc` + 全量用例是唯一能兜住
「别的页面间接受影响」的手段。后端未改时不必跑 `mvn test`。
